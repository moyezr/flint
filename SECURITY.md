# Security policy

## Supported versions

Security fixes are made on `main` and included in the next official beta or
release. Older direct-beta builds may not receive separate patches.

## Reporting a vulnerability

Please do not open a public issue for a vulnerability that could expose user
data, bypass download or licensing controls, abuse the update channel, or allow
unintended microphone, Accessibility, insertion, or Keychain behavior.

Email `moyezrabbani.work@gmail.com` with the subject `Flint security report` and
include:

- The affected version or commit.
- The macOS and hardware version when relevant.
- Reproduction steps or a minimal proof of concept.
- The expected impact and any suggested mitigation.

You should receive an acknowledgement within seven days. Please allow a
reasonable period for investigation and release coordination before publishing
details.

Never include real license keys, database credentials, email-provider secrets,
private signing keys, OTP values, or another person's transcript in a report.
